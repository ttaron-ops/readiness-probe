The one shift everything else follows from

In Python, a variable is a name bound to an object. In Go, a variable is the value — a box with bytes in it. Assignment copies the box.

Once that lands, zero values, pointer receivers, struct padding and escape analysis all stop being separate topics and become consequences of the same fact.

Except when it doesn't

Having just learned "Go copies," here is the trap: slices, maps and channels are small headers that point at shared data. Copying the header copies the pointer.

The rule to carry

Structs and arrays copy. Slices, maps and channels share. When you need a genuinely independent slice, slices.Clone or an explicit copy() — never assignment.

Threenil

Four nils, four behaviours

Python has one None and it does nothing. Go's nil is typed, and what it does depends on the type.

nil slice

append works. len is 0. Ranging over it is a no-op. A nil slice is a perfectly good empty slice — do not guard against it.

nil map — reading

Returns the zero value, len is 0, ranging is a no-op. Reads are safe.

nil map — writing

Panics. assignment to entry in nil map. A map must be made before it can be written.

nil pointer

Dereferencing panics — the familiar one. But a nil pointer with a pointer receiver method can still be called safely if the method doesn't dereference.

Fiveerrors

Nothing is thrown

Python — control flow

An exception unwinds the stack until something catches it. The signature does not mention it, so you learn what can fail by reading the body, or by production.

Go — a value

func parse(s string) (int, error). Failure is in the type. Nothing unwinds; if you ignore the error, execution continues with a zero value.

panic is not an exception

It exists, and it is not the error mechanism. Panic means "this program has a bug and cannot continue" — nil dereference, index out of range, a broken invariant. Library code that panics on bad input rather than returning an error is considered badly written.

Drills

You pass a struct to a function and it modifies a field. Does the caller see it?

No. Parameters copy, and a struct copies by value. The caller sees nothing.

To let it modify, take *T — which also documents the intent in the signature. This is the single most important difference from Python.

You pass a slice to a function and it does s[0] = 99. Does the caller see it?

Yes. A slice is a header — pointer, length, capacity — and copying the header copies the pointer to the shared backing array.

But if the function appends and the append reallocates, the caller sees neither the new elements nor further writes. Whether it reallocates depends on cap(), which the call site cannot see.

Is a nil map safe to use?

Safe to read — returns the zero value, len 0, ranging is a no-op. Writing panics with assignment to entry in nil map.

A nil slice, by contrast, is safe to append to and is a perfectly good empty slice. Do not write if s == nil guards around slices.

func f() error { var p *MyErr; return p }. Is f() == nil?

No — and this is the most famous bug in Go. An interface holds a type and a value, and is nil only when both are. Returning a nil *MyErr gives an interface with type *main.MyErr and value nil, which is not nil.

Every if err != nil downstream fires. Return the literal nil.

How does a type declare that it implements an interface?

It doesn't. Satisfaction is implicit and structural — if the method set matches, the type satisfies it, and the compiler checks at the point of assignment.

Which is why interfaces are usually declared by the consumer: define the one- or two-method interface you need, and types you don't own already satisfy it.

Why does encoding/json ignore your field?

It is lowercase. Capitalisation is the access modifier — enforced by the compiler, not a convention — and unexported fields are invisible to other packages, including the json encoder.

The Python instinct that _name is "private by agreement" does not transfer; here it is mechanical.

What is panic for?

Programmer error — a broken invariant, a nil dereference, index out of range. Not the error mechanism. Errors are returned values.

Library code that panics on bad input instead of returning an error is considered badly written.
